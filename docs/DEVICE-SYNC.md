# Linked-device replication and delegated actions

Existing `history` certificates and manual archives remain supported. A new explicitly selected `history-live` scope is signed with the existing root key and domain `VO1D-DEVICE-LINK-2`. The peer must compare fingerprints, confirm the link locally and use this version. Scope changes invalidate the signature; a manual certificate cannot authorize live snapshots.

When the primary app completes synchronization, it prepares a bounded snapshot of the last 200 nonexpired text/poll messages. The snapshot excludes files, one-view content, drafts, receipt lists, edit history, notes, ratchet state and capabilities. It replaces a stable per-link archive on the peer. New messages, edits and deletions appear in the next delivered snapshot. A digest suppresses unchanged snapshots; only one exact persisted delivery is in flight per link. A monotonically increasing revision survives restarts and rejects older/repeated snapshots even if transport ordering changes. Delivery uses the existing libsignal session and private route when available.

The receiver verifies the signed certificate, approved peer identity, audience, live scope, archive ownership/limits and revision, and requires the peer still be verified and unblocked. Revocation removes queued deliveries immediately and leaves a tombstone until certificate expiry. Received revocations also remove queued deliveries. Outbox sending rechecks that an entry was not canceled while preparing its keys/route.

The independently selected `collaboration` scope adds text/file sending, own-message edits/deletions and private-link revocation **through the primary device**. It uses the same signed certificate domain with a new scope; existing `history`/`history-live` certificates do not gain sending/file authority. Both ends must compare fingerprints, verify the contact and approve the link. The primary checks certificate issuer/audience/signature/expiry, current approval, verified contact, block state and revocation on each request.

Secondary requests are persisted E2EE events. The primary rechecks the current local room, membership, group posting permissions, blocked recipients, expiry and message ownership. It uses its own root key and ordinary libsignal queue; no primary private key is copied. A command UUID becomes a deterministic outgoing message ID. The dedup result and outgoing queue commit together before ACK; retrying a command does not send another message. Results mean queued/applied/rejected, not an assertion of recipient delivery. Requests expire after seven days, dedup records are retained eight days and bounded at 10,000; pending secondary requests are capped at 128. The archive displays pending/result state and has retry, file, edit and delete controls. Independent account backups strip these delegated requests/authorities.

Collaboration snapshots may include read capabilities and keys for ordinary encrypted blobs, with explicit file authority at pairing. The secondary can download only those shared files and verifies the blob digest/AEAD through the existing API. One-view files/text are excluded. Inline file content is not replicated; older legacy account blobs without independent read capability are omitted. Secondary-selected files up to 50 MB are encrypted/uploaded using its own independent blob capabilities; only the resulting metadata/keys go in the E2EE command. The primary validates them through its normal attachment rules. Originals still obey endpoint expiry/deletion and copied downloads cannot be erased remotely.

Up to 32 primary private-link records share only `SHA256(VO1D-DEVICE-LINK-REF-1 + ownerID + token)`, expiry and revocation state. The invitation token, encryption key and mailbox credentials are omitted. A scoped request references that hash; the primary marks its own record for durable revocation. Already redeemed chat addresses need separate revocation.

Both apps must eventually run with network access; the secondary can queue requests while the primary is offline, but delivery waits for it. iOS cannot provide arbitrary permanent background polling. This does not implement independent secondary calling, concurrent account-key recovery or conflict-free concurrent edits; arriving authorized edits execute in primary receive order and snapshots converge to its state. A peer may save history/files already received; revocation cannot erase those copies. Certificates expire after 30 days. Older apps require manual history mode and must not be granted collaboration authority.
