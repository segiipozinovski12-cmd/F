# Сборка и запуск на iPhone

Для свежей копии на Mac:

```bash
git clone --recurse-submodules --branch codex/vo1d-next https://github.com/segiipozinovski12-cmd/F.git VO1D-Messenger
cd VO1D-Messenger
bash scripts/open_iphone.sh
```

В уже обновлённой копии ветки `codex/vo1d-next`, из корня репозитория:

```bash
bash scripts/open_iphone.sh
```

Нужны Xcode с iOS SDK и Python 3.8+. Скрипт загружает закреплённые libsignal и Tor, генерирует проект, собирает unsigned Debug для физического iPhone и проверяет встроенные frameworks. Rust и Homebrew не требуются. Затем он открывает Xcode: выбери свой Team, подключённый iPhone и нажми `⌘R`. Проверочная unsigned сборка сама по себе не устанавливается на устройство; подпись и установку выполняет Xcode.

Запускай без `sudo`. До загрузки SDK скрипт проверяет запись в `build/iphone-validation` и задаёт эту папку в локальных настройках проекта Xcode. Подготовка зависимостей и проверочная сборка также получают явный `-derivedDataPath`: повреждённая или недоступная глобальная `~/Library/Developer/Xcode/DerivedData` больше не нужна этому проекту. Остальные настройки Xcode сохраняются. Если проект открыт, закрой его перед запуском скрипта и открой заново после завершения. Полный вывод `xcodebuild` сохраняется в `build/iphone-validation.log`.

Это устраняет зависимость проекта от глобальной папки кэша. Если недоступна и локальная папка или на диске нет места, скрипт завершится с причиной до сборки. Другие ошибки компиляции или подписи нужно определять по первой ошибке в логе.

Debug использует пустые push entitlements и не регистрируется в APNs/PushKit. Personal Team подходит для проверки интерфейса, переписки и звонков при открытом приложении. Release сохраняет push и VoIP capabilities: для них нужны подходящие Apple provisioning и серверная конфигурация. Генератор сохраняет Team и Bundle Identifier из существующего проекта; при необходимости их можно задать переменными `VO1D_DEVELOPMENT_TEAM` и `VO1D_BUNDLE_ID`.

## Исправленные причины ошибок

- Tor для iOS должен иметь `Info.plist` и executable в корне framework. Подготовка превращает versioned framework в shallow bundle, следует выбранной `Versions/Current`, для динамических slices исправляет Mach-O install name на `@rpath/tor.framework/tor` и удаляет старую подпись перед подписью встроенной копии средствами Xcode. Статические архивы не имеют install name и не обрабатываются как dylib.
- Генератор больше не заменяет уже собранную из исходников библиотеку libsignal готовым архивом другой конфигурации. Native FFI помещается в отдельный shallow framework, который экспортирует только `signal_*`; внутренняя BoringSSL не смешивается с OpenSSL из Tor. C-объекты LLVM IR материализуются до финального связывания, чтобы native LTO не загружался слишком поздно. Оригинальный SDK-архив сохраняется.
- Возврат после временной недоступности защищённых данных повторяет полную загрузку и миграцию хранилища. На экране ошибки есть повтор после разблокировки; перед активной сессией приложение пробует восстановление автоматически.
- Ошибка чтения vault блокирует запись и фоновые обработчики, чтобы пустое состояние не заменило существующий файл. Смена сетевого маршрута сначала авторизует аккаунт, затем проверяет возможности relay.
- Некорректный сохранённый адрес relay не объявляется ошибкой защищённого хранилища: локальные данные и настройки остаются доступны для исправления подключения.
- Одна генерация профиля не начинает несколько подключений одновременно. После переключения профиля старое подключение не блокирует новую попытку.
- Debug не требует платных push capabilities, а plist поддерживает все ориентации iPad.

## Проверки

```bash
python3 -m unittest discover -s scripts/tests -v
python3 -m unittest discover -s server/tests -v
```

Проверки подготовки SDK охватывают сохранение существующего архива, неоднозначный выбор библиотеки, версии и symlinks Tor, а также недопустимый bundle layout. XCTest проверяет восстановление Keychain/vault и миграцию credentials. Серверный тест квот использует фиксированное время, чтобы смена минутного окна не давала случайный отказ CI.

GitHub Actions настроен на macOS 15 и 26: Simulator Debug, XCTest, device Debug и Release, проверка embedded frameworks и снимок первого запуска. Это не заменяет проверку установки с твоим Apple Team, мобильной сети и фоновых звонков на физическом телефоне. Relay должен поддерживать `/v2/capabilities`; сборка приложения не обновляет развёрнутый сервер.
